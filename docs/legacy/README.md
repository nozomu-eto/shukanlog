# 旧リポジトリ(Amplify版)から引き継ぐ資料

旧リポジトリ `shukanlog-amplify` から、新リポジトリでも使う内容だけを抜き出したもの。**そのままビルドに含めるコードではなく、移植の元にする参照用の資料**。移植が済んだら、このフォルダは削除してよい。

| ファイル | 内容 | 移植先と注意点 |
|---|---|---|
| terms.md | 利用規約の本文 | `/terms` ページの本文。第9条2項は退会の仕様(30日間保管後に完全削除、30日以内のログインで取り消し可)に合わせて書き換える |
| privacy.md | プライバシーポリシーの本文 | `/privacy` ページの本文。下記「プライバシーポリシーで直す箇所」を反映する |
| limits.ts | 入力上限の定数 | `src/shared/` 配下。サーバーとフロントエンドの両方から参照する |
| date.ts | 日付のユーティリティ | `src/shared/domain/` 配下。「今日」の判定を日本時間で明示的に行う形に書き直す |
| initial-habits.ts | 初期データ(服薬・運動)の定義 | 利用規約への同意時に作成する初期データ |
| email-templates.md | 認証メールの文面 | メールのテンプレート関数。有効期限は10分 |

## プライバシーポリシーで直す箇所

1. 1章「運動記録(実施日、内容、時間・距離・回数等の数値情報)」→ 実際の記録は3段階の評価(できた・少し・できなかった)なので、「運動の実施状況の記録」に直す
2. 8章「削除は原則として即時に行われます」→「退会後30日間は保管し、その後完全に削除します。30日以内に同じメールアドレスでログインすると退会を取り消せます」に直す
3. 1章に「お問い合わせ」以外に、新規登録時の bot 対策(Cloudflare Turnstile)で端末・ブラウザの情報が処理されることを追記するか検討する(5章の委託先の業務カテゴリに「不正利用の防止」を加える形でもよい)
4. 最終改定日を公開日に更新する

## 引き継がないもの

- Next.js・Amplify・Cognito・AppSync・DynamoDB・Lambda 関連のコード、設定、テスト一式
- `customHttp.yml`、`amplify_outputs.json`
- `docs/hardening-progress.md` などの Amplify 版の作業記録(経緯を残したい場合は旧リポジトリを参照する)
- `docs/email-sending.md`・`docs/bot-protection.md` の Amplify 固有の手順(Cloudflare 側の手順は、新リポジトリの `docs/production-verification.md` で書き直す)
