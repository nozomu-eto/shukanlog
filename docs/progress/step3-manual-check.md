# ステップ3 画面の動作確認(手動確認手順)

この環境ではブラウザを実際に操作できるツールが無かったため、`wrangler dev` を起動し、curlでAPIレベルの一連の流れ(新規登録→確認コード→自動ログイン→同意→日タブの記録取得/保存/取り消し→カロリーの作成/編集/削除→ログアウト→ログイン)が成立することを確認した(結果は docs/progress/step3.md のT15参照)。

画面(React側)を実際にブラウザで操作して確認する場合は、以下の手順で行う。スマホ幅(390px程度)とPC幅(1280px程度、ブラウザの開発者ツールでレスポンシブ表示にする)の両方で確認する。

## 準備

1. `.dev.vars.example` を `.dev.vars` にコピーし、`BETTER_AUTH_SECRET` をランダムな32文字以上の文字列に置き換える
2. `pnpm run db:migrate:local` でローカルD1にマイグレーションを適用する
3. `pnpm run build && pnpm exec wrangler dev` でサーバーを起動する(または `pnpm dev` でViteの開発サーバーを使ってもよい)
4. 確認コードは開発用のメール送信(console)のため、ターミナルのログに出力される

## 確認項目(スマホ幅・PC幅の両方で)

### 新規登録〜同意まで

- [ ] `/` を開き、見出し・「無料ではじめる」「ログイン」ボタン・週のふりかえりの例・3つの特徴・フッターのリンクが表示される
- [ ] 「無料ではじめる」から `/signup` へ進み、メールアドレス・パスワード(8文字未満でエラーになること)を入力し、Turnstileのウィジェット(テスト用キーのため自動的に成功する)が表示される
- [ ] 「確認コードを送る」を押すと `/verify` に進み、ターミナルのログに出た6桁のコードを入力して「確認する」を押すと、そのまま `/consent` に進む(ログイン画面を経由しない)
- [ ] 「確認コードを再送する」を押すと60秒間ボタンが押せなくなり、残り秒数が表示される
- [ ] `/consent` でチェックを入れずに「同意してはじめる」を押すとエラーが表示され、チェックを入れて押すと `/app` (日タブ)に進む

### 日タブでの記録

- [ ] 日タブのヘッダー(スマホ: サービス名+設定アイコン、その下に日・週・月の切り替え / PC: サービス名・切り替え・設定が横並び)が表示される
- [ ] 初回(今日の記録が無い状態)は「今日の記録をはじめましょう」の案内が表示される
- [ ] 服薬(◯/×)・運動(◯/△/×)のボタンを押すと即座に見た目が変わり(押した瞬間の保存)、画面下に「保存しました」のトーストが2秒表示される
- [ ] 選択中のボタンをもう一度押すと未選択に戻り、「記録を取り消しました」のトーストが出る
- [ ] 「次の日」は今日の間は押せない(薄い表示)。「前の日」で過去に移動すると「今日に戻る」ボタンが出る
- [ ] カロリーのカードの「記録する」からダイアログ(スマホは下からのシート、PCは中央)が開き、最初の入力欄(カロリー)に自動でフォーカスされる。カロリーに10001や小数を入力するとエラーが出る
- [ ] 保存すると、ダイアログが閉じてカロリーの合計・一覧に反映され、「保存しました」のトーストが出る
- [ ] 記録の行を押すと編集ダイアログが開き、「この記録を削除する」→確認文言→「削除する」の順で削除でき、一覧から消える
- [ ] ダイアログを開いた状態でEscキーを押すと閉じ、フォーカスが開いたボタンに戻る

### ログアウト・ログイン

- [ ] `/app/settings` の「ログアウト」を押すと `/login` に移動し、見出しの上に「ログアウトしました」と表示される
- [ ] 誤ったパスワードでログインするとエラーが表示される
- [ ] 正しいメールアドレス・パスワードでログインすると `/app` に進む(同意済みのため `/consent` を経由しない)

### パスワードの再設定

- [ ] `/reset` で登録済みのメールアドレスを入力し、届いたコードと新しいパスワードを `/reset/new` で入力すると、`/login` に「パスワードを変更しました」と表示された状態で戻る
